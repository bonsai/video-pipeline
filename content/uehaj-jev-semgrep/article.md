# 意味で探すgrep「jev-semgrep」徹底解説 — なにができるかと原理

著者: bonsai の Jev 解説シリーズ / 対象repo: [uehaj/jev-semgrep](https://github.com/uehaj/jev-semgrep)

## これは何か

「正規表現ではなく**意味**で行を探す grep」です。grep が文字列の**記号の一致**を見るのに対し、
jev-semgrep は行の**意味の一致**を判定します。

判定には [TypeSafe AI](https://typesafe.ai/) の System One モデル **Jev** を使います。
Jev は文章を生成せず、**typed な質問に対して確率だけを返す**モデルです。そのため
「この行は『ネットワーク障害』の意味に合うか(yes/no)」という質問を1行ずつ投げ、
返ってきた確率を閾値で切るだけで意味検索ができます。

```sh
./semgrep -n -e "顧客が怒っている、または不満を持っている" tickets.txt
```

## なにができるか

### 1. 概念で探す。言語を問わない

`grep "angry"` は文字列 `angry` が無ければ何も引っかかりません。jev-semgrep は次の例で、
**どの行にも angry/frustrated という語が無い**のに、日本語の問い合わせ行まで拾っています。

```
$ ./semgrep -n -e "customer is angry or frustrated" tests/corpus.txt
14:ユーザー山田さんからの問い合わせ: 返金してほしい、商品が壊れていた
16:ユーザー佐藤さんからの問い合わせ: 注文した覚えのない請求が来ています。至急確認してください
18:I want my money back. The item arrived broken and customer service ignored me.
```

### 2. 多言語横断

Jev は語ではなく**概念**を照合するので、日本語の意味で英語の行も、その逆も同確信度で見つかります。
`tests/multi.txt` には仏・露・独・西・中・韓の文が入っており、日本語の意味 **1つ**で
6言語すべての「返金要求」がヒットします。

### 3. AND / OR / NOT がそのままブール演算になる

意味ごとに**独立した確率**が出るため、確率を置き換えせずに論理演算できます。

```sh
# 返金の話だが、顧客が求めているのではない → 完了報告、ポリシー、却下、日数
./semgrep -n -e "about a refund" -v "the customer is asking for a refund" tests/contrast.txt

# 怒っている、かつ、それが顧客であってスタッフではない
./semgrep -n -e "someone is angry" -a "the customer, not the staff, is the one acting" tests/contrast.txt
```

「ネットワーク障害のうちリトライ中を除く」「金融AND悪いニュース OR 天気」のように
複合クエリも1コマンドで書けます。

### 4. 厳しさのプリセットと、grep 互換の使い勝手

`--level loose/normal/strict` で閾値を一括制御。`-r`(再帰)・`-l`(ファイル名のみ)・
`-A/-B/-C`(文脈行)・`-c`(行数)・`-p`(確率表示)・`--color` など grep の慣れた操作も揃っています。
FILE 省略時は stdin。終了コードも grep と同じ(0=一致あり/1=なし/2=エラー)。

## 原理の深掘り

### 仕組みの4ステップ

1. 空行を除いた行を **30行ずつ**のチャンクにする(文字数上限つき)
2. チャンクを `{"L000": "行1", "L001": "行2", ...}` として `state` に入れ、
   **行数×意味数**の分だけ `noul`(yes/no確率)質問を **1リクエストにまとめて**送る
3. **8本まで並列**にリクエストし、結果はファイル順に出力
4. 各確率を閾値で真偽に変え、AND/OR/NOT 式を評価

### なぜベクトル検索と違うのか(cross-encoder vs bi-encoder)

「X に関係のある行」だけなら埋め込みのコサイン類似度でも同じ行が出ます。
違いは **判定の中身**です。

- **bi-encoder**(埋め込み/コサイン類似度): 行のベクトルは質問を見る**前に**固定される。
  測れるのは「話題の近さ」まで。
- **Jev は cross-encoder 型**: 行と質問を**同時に**読んで答える。
  だから「誰が何をしたか」「否定」「求めているのか済んだのか」で答えが変わります。

README の `tests/contrast.txt` の例が決定的です。次の6行はどれも「返金の話」ですが、
「顧客が返金を求めている」のは2行だけです。

```
1:返金してほしい。商品が壊れていた                           [0.98]
2:返金処理が完了しましたのでご確認ください                    [0.10]
3:当社の返金ポリシーは購入後30日以内です                     [0.10]
4:The manager denied the refund request yesterday            [0.17]
5:I demand a full refund immediately                         [0.94]
6:Refunds are processed within 5 business days               [0.08]
```

「カスタマーサポート担当者が怒って電話を切った」と「顧客が怒って電話を切った」は
コサイン類似度がほぼ1ですが、Jev は主語(誰が)で判定を分けられます(前者は0.05で除外)。

### 実用上の帰結

- **確率は較正済み**なので、質問によらず閾値0.5が使える(top-kや質問ごとの閾値調整が不要)
- **索引を作らない**。目の前のファイルにそのまま当てられる
- 裏返すと、問い合わせのたびにコーパス全体分を払うので、**同じ大きいコーパスを何度も**調べるなら
  ベクトル索引の方が安くて速い(どちらを使うかは「1回のふるい」か「繰り返し照会」かの違い)

### 性能とコスト

- 30行で1リクエスト約0.2秒、1行ずつだと約7秒。既定30行がバランス点
- 確率は実行ごとに±0.05ほどぶれる。閾値を詰めるなら `-p` で実測を見る
- 料金は入力100万トークンあたり0.042ドル(2026年9月時点)。2意味×30行 ≈ 3,000トークン
- レート制限1,200リクエスト/分が上限で、既定設定なら毎分およそ36,000行

### テストは LLM-as-judge

`tests/` には精密/再現率を出す LLM-as-judge テストが入っています。51行のコーパスに10ケースを投げ、
Claude が「各意味に本当に合致する行」を判定して照合し、precision / recall を計算。
閾値を0.05刻みで総当たりして最良値も報告(直近: precision 0.94 / recall 0.98)。

## 制約(読む前に)

- **検索した行はすべて api.typesafe.ai に送られます**。送りたくないファイルには使わない
- 精度は英語が最も高く、日本語は使えるが閾値付近でぶれは大きめ
- 1行2,000文字まで。空行は確率0扱い
- 429/529 は指数バックオフで6回リトライ

## まとめ

jev-semgrep は「grep を意味まで格上げした最小実装」です。依存ゼロ1ファイルで、
cross-encoder 型モデルの強み(主語・否定・時制まで見る判定)と、確率にブール演算を
重ねる設計を、シンプルな CLI へ落とし込んでいます。静的分析ツールの
[Semgrep](https://semgrep.dev/) とは**同名別物**なので注意。
